# تجهيز ونشر عقار البطين على iOS

## إعدادات ثابتة من المشروع
- اسم التطبيق: عقار البطين
- Bundle ID الحالي في capacitor.config.ts: cloud.baytialkhass.app
- Apple Team ID الذي زوّدني به صاحب المشروع: B7864TA42J
- مصدر الأيقونة: public/logo.jpg
- الحد الأدنى لـ iOS في مشروع Capacitor: iOS 15

> لا تغيّر Bundle ID بعد إنشاء سجل التطبيق أو رفع أول Build؛ يجب أن يطابق App Store Connect والـ provisioning profile.

## بناء وتوقيع نسخة TestFlight
شغّل GitHub Actions workflow:
.github/workflows/ios-testflight-release.yml

الـ workflow يستخدم macOS 26 / Xcode 26، ويولّد مشروع iOS، ثم يصنع أيقونة 1024×1024 من public/logo.jpg، ويؤرشف التطبيق ويوقّعه ويصدّر IPA. يمكنه رفع IPA إلى App Store Connect/TestFlight بعد التوقيع.

### Secrets المطلوبة في GitHub
من Settings → Secrets and variables → Actions أضف الأسماء التالية فقط؛ لا تضع قيم الأسرار في الكود أو في المحادثات:
- APPLE_CERTIFICATE_P12_BASE64: شهادة Apple Distribution بصيغة P12 بعد تحويلها إلى Base64.
- APPLE_CERTIFICATE_PASSWORD: كلمة مرور ملف P12.
- APPLE_PROVISIONING_PROFILE_BASE64: ملف App Store distribution provisioning profile المطابق لـ Bundle ID وTeam ID.
- APP_STORE_CONNECT_API_KEY_ID: Key ID لمفتاح App Store Connect.
- APP_STORE_CONNECT_ISSUER_ID: Issuer ID.
- APP_STORE_CONNECT_API_PRIVATE_KEY: محتوى ملف المفتاح الخاص P8.

لا يمكن إنشاء الشهادة أو ملف provisioning profile أو مفتاح App Store Connect من Team ID وحده؛ يجب أن يُنشأوا من حساب Apple Developer/App Store Connect المخوّل.

عند تشغيل workflow يدويًا أدخل عنوان HTTPS عامًّا وثابتًا للتطبيق في server_url. الـ workflow لا ينشر الموقع أو الخادم؛ التطبيق الحالي يعتمد على عنوان الخادم لتشغيل واجهات TanStack server/API. لا تستخدم عنوان معاينة مؤقتًا. إذا كان المطلوب عدم استخدام Vercel إطلاقًا، فيجب أن يكون هذا العنوان لخادم بديل مستضاف بالفعل؛ إزالة العنوان من دون نقل واجهات الخادم ستعطّل تسجيل الدخول والـ API والدفع.

إذا اكتمل الرفع، سيظهر Build في App Store Connect بعد أن تعالجه Apple. الرفع وحده لا يضمن اجتياز TestFlight beta review أو App Review، ولا يضيف المختبرين تلقائيًا؛ أكمِل إعدادات TestFlight ومعلومات المراجعة داخل App Store Connect.

## متطلبات لا تزال تحتاج فحصًا/قرارًا قبل الإرسال
1. **حذف الحساب:** تمت إضافة خيار حذف الحساب مع تأكيد واضح في صفحة حساب الفردي وملف المكتب، وربطه بتنظيف بيانات الحساب والإعلانات والمحادثات والوسائط المملوكة له مع إلغاء ربط سجل المعاملات المالية من الحساب. يجب اختبار الحذف على حسابات فردية ومكاتب تجريبية والتحقق من السجلات والملفات قبل إرسال النسخة.
2. **الدفع:** التطبيق يستخدم HyperPay للاشتراك الاحترافي الذي يفتح مزايا داخل التطبيق. يجب حسم آلية الدفع المناسبة لقواعد App Store للمتجر/المنطقة المستهدفة قبل إرسال النسخة؛ لا تفترض أن بوابة دفع خارجية مقبولة تلقائيًا لفتح المزايا الرقمية.
3. **الإشعارات:** تم تصحيح تسجيل توكن الجهاز ليحفظ منصة iOS الصحيحة ويربط التوكن بالحساب الحالي ويزيل الربط عند تسجيل الخروج. ما زال اختبار APNs على جهاز iPhone حقيقي وإرسال push من الخادم مطلوبين؛ لم أتحقق من وجود مُرسل APNs فعّال أو مفاتيح APNs في بيئة الخادم.
4. **سياسة الخصوصية:** ملف public/privacy.html ما زال مسودة للمراجعة. لتجنب Vercel، أضفت workflow يدويًا باسم .github/workflows/publish-ios-legal-pages.yml ينشر سياسة الخصوصية والدعم فقط على GitHub Pages بعد مراجعة النص وتأكيد النشر. يلزم أولًا تفعيل Settings → Pages → GitHub Actions، ثم تشغيل workflow مع publish_confirmed=true. الروابط المتوقعة بعد نجاح النشر: https://ffgg35646-ops.github.io/new2/privacy.html و https://ffgg35646-ops.github.io/new2/support.html.
5. **صور المتجر:** خذ صورًا حقيقية من نسخة iPhone النهائية لأهم الشاشات (الرئيسية، تفاصيل العقار، المكتب، المحادثة، والحجز). صورة المحاكي من اختبار smoke وحدها ليست مجموعة صور متجر كاملة.
6. **اختبارات فعلية:** نجاح بناء وتشغيل المحاكي لا يعني أن مسارات التسجيل والتحقق بالبريد والدفع والإشعارات قد اجتازت الاختبار. يلزم حسابات اختبار وبوابة دفع sandbox وبيئة قابلة للاختبار، ثم التأكد من النتائج من السجلات.
7. **روابط المتجر:** روابط GitHub Pages أعلاه لا تصبح متاحة إلا بعد تفعيل Pages وتشغيل workflow بنجاح؛ لم يتم نشر هذه الصفحات حتى الآن. قبل النشر، راجع السياسة لمدى مطابقتها الفعلية للبيانات والمزودين والاحتفاظ، ثم أدخل رابط الخصوصية ورابط الدعم، والفئة والتصنيف العمري والحقوق ومعلومات المراجعة وبيانات التواصل في App Store Connect.
